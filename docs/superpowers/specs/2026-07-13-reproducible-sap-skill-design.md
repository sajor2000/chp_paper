# Reproducible Statistical Analysis Plan Skill Design

**Date:** 2026-07-13
**Status:** Approved refinement of the ChicagoHealthMap scientific-pipeline design

## Purpose

Deliver one study-ready ChicagoHealthMap statistical analysis plan (SAP) workbook and a reusable Codex skill that can create the same class of governed SAP for later biomedical, public-health, and health-services projects. The repository copy is canonical; a global Codex symlink exposes it across projects without creating two divergent skill copies.

## Product contract

Every generated workbook begins with exactly these three operational sheets, modeled on `SBTSAP_Analysis_Plan_v4.xlsx`:

1. `Overview` — one row per analysis, with claim, unit, data, question, primary method, secondary methods, and script/output owner.
2. `Outputs` — a section-banded output manifest linking deliverable, cohort/scope, method section, contents, owner, and interpretation.
3. `Master Variables` — a governed data dictionary with category, variable, definition, type, values, source file, analysis membership, and resolved decisions.

The visual language is Calibri 10, dark-blue `#1F4E79` headers with white bold text, alternating white/light-gray rows, blue section bands, restrained category colors, wrapped text, filters, and frozen panes. The skill adds accessibility, validation, provenance, and scientific annexes but does not decorate the workbook with nonessential charts.

## Scientific contract

The workbook is a prespecification and decision-control artifact, not merely a table shell. It must support:

- explicit research questions and estimands;
- populations, units, time windows, geography, exposures, outcomes, covariates, and transformations;
- numerator, denominator, missingness, suppression, reliability, coverage, and representativeness semantics;
- outcome-blinded selection where applicable;
- primary models, diagnostics, spatial or clustered-data gates, multiplicity families, sensitivity analyses, and negative-control decisions;
- reporting-rule mapping (STROBE, RECORD, STROBE-Equity, SAGER, and target-journal rules as applicable);
- decision, deviation, freeze, source, and output lineage;
- permitted and prohibited interpretation language.

The generic skill must never invent unresolved scientific choices. Unknown choices are labeled `PENDING`, paired with an owner and gate. It must distinguish descriptive, primary, secondary, sensitivity, and exploratory work. It must never imply that an observational association is causal or that an EHR proportion is population prevalence without a validated target-population estimand.

## Architecture

- `skills/create-statistical-analysis-plan/SKILL.md` defines the reproducible workflow.
- `skills/create-statistical-analysis-plan/scripts/build_sap.mjs` builds an `.xlsx` from a versioned JSON study specification.
- `skills/create-statistical-analysis-plan/scripts/validate_sap.mjs` enforces sheet, column, error, and governance contracts.
- `skills/create-statistical-analysis-plan/references/` holds the workbook pattern, scientific rigor, and specification schema.
- `skills/create-statistical-analysis-plan/assets/SAP_Analysis_Plan_Template.xlsx` is a generic starter generated by the same builder.
- `docs/analysis/sap_workbook_spec.json` is the ChicagoHealthMap study-specific input.
- `outputs/019f5d68-66a6-74a1-8692-aa10ec6f8497/ChicagoHealthMap_Draft_SAP.xlsx` is the current deliverable.

The builder contains presentation and contract logic only. It does not analyze patient data, fit models, or bypass the ChicagoHealthMap S4-S6 authorization gates.

## Evidence basis

The reusable rules are grounded in PubMed and Paperclip evidence on observational SAPs and prespecification (including DEBATE, Pre-SPEC, TARMOS, and estimand guidance), and in current official JAMA Health Forum, RECORD, STROBE, STROBE-Equity, and SAGER sources. Tavily was exposed but returned `monthly_cap_reached_bonus_eligible`; it contributed no evidence. Ref Context was available for technical documentation but did not surface an authoritative Agent Skills specification, so the installed OpenAI skill-creator and Superpowers writing-skills instructions govern packaging.

## Installation and ownership

The repository directory is the source of truth. A local agent may symlink the `skills/create-statistical-analysis-plan` directory into its configured skills directory. Changes are reviewed and committed in the project before becoming globally available. Generated study workbooks and specifications remain in their study repositories; the skill contains no patient data, credentials, or study-specific secrets.

## Acceptance criteria

- The first three sheets and their columns match the reference pattern.
- The ChicagoHealthMap workbook retains the study's scientific gates and noncausal interpretation boundaries.
- The generic template can be rebuilt from a minimal specification.
- The validator reports no missing required sheets/columns and no spreadsheet formula errors.
- Every sheet renders legibly under artifact-tool inspection.
- The skill passes `quick_validate.py` and its executable examples pass from a clean invocation.
